# jaiye-agent v0.2 — Universal Coordination

## Problem

v0.1 assumes git repos and code. File ownership uses `git diff` and commit prefixes. Handoffs capture branch state. The `check` command runs against PRs. Every core path depends on git.

This means jaiye-agent cannot coordinate agents working on video edits, content production, research projects, design files, or any workflow where the artifacts aren't source code in a git repo.

The Cowork + Codex bridge protocol (built ad hoc for a CapCut video editing project) proved the concept works for non-code: structured handoffs, role specialization, file ownership, and conflict detection all apply. But the bridge was a markdown file with no tooling. jaiye-agent should be that tooling.

## Goals

1. Run jaiye-agent outside git repos (any folder)
2. Add Cowork as a first-class agent type alongside Claude Code, Codex, Gemini CLI
3. Support non-code artifacts in handoffs (spreadsheets, project files, media references)
4. Keep full backward compatibility with v0.1 git-based workflows

## Architecture Changes

### 1. Dual Mode: Git and Standalone

**Change:** Introduce a mode detector.

```typescript
// src/core/mode.ts
export type ProjectMode = 'git' | 'standalone';

export function detectMode(): ProjectMode {
  // Try git rev-parse. If it fails, return 'standalone'.
}

export function getProjectRoot(): string {
  // git mode: git rev-parse --show-toplevel
  // standalone mode: walk up from cwd looking for .jaiye/
  // fallback: cwd
}
```

**Files to change:**
- `src/utils/paths.ts` — replace `getRepoRoot()` with `getProjectRoot()`, wire through mode detection
- `src/core/git.ts` — guard every function with mode check, return empty/defaults in standalone mode
- `src/commands/init.ts` — detect mode, skip git-specific setup in standalone mode
- `src/commands/check.ts` — in standalone mode, use file modification timestamps instead of git diff

### 2. Agent Type System

**Current state:** `AgentDef` in `src/types.ts` has `name`, `description`, `commit_prefix`. All agents are treated identically. No concept of agent capabilities or interaction patterns.

**Change:** Add an `agent_type` field and capability declarations.

```typescript
// Updated AgentDef
export interface AgentDef {
  name: string;
  description: string;
  commit_prefix?: string;     // optional in standalone mode
  type?: 'cli' | 'desktop' | 'ide' | 'custom';
  capabilities?: string[];    // e.g. ['file_io', 'code_gen', 'mcp', 'web_search']
  bridge?: string;            // path to bridge file for async agents
}
```

Predefined agent templates:

| Type | Example | Default Capabilities |
|------|---------|---------------------|
| `cli` | Claude Code, Codex, Gemini CLI | code_gen, file_io, git |
| `desktop` | Cowork | file_io, mcp, document_gen, web_search |
| `ide` | Cursor, Copilot | code_gen, file_io, inline_edit |
| `custom` | User-defined | explicit declaration |

**Files to change:**
- `src/types.ts` — extend `AgentDef`
- `src/core/agents-md.ts` — render agent types and capabilities in AGENTS.md
- `src/commands/init.ts` — offer agent templates during setup

### 3. Standalone Ownership Tracking

**Current state:** `src/core/ownership.ts` calls `identifyAgent()` from `git.ts`, which matches commit message prefixes. No git = no ownership tracking.

**Change:** In standalone mode, track ownership via a `.jaiye/state.json` file that records which agent last touched which file, updated explicitly via CLI commands or file watchers.

```typescript
// src/core/state.ts
export interface ProjectState {
  version: number;
  files: Record<string, {
    assigned: string;        // from config ownership rules
    last_touched_by: string; // from explicit registration
    last_modified: string;   // ISO timestamp
    artifact_type?: string;  // 'code' | 'document' | 'media' | 'config' | 'data'
  }>;
  updated: string;
}
```

New commands for standalone mode:

```bash
# Register that an agent touched files
jaiye-agent touch --agent cowork "reel_edit_sheet.xlsx" "source_map.json"

# Sync state from filesystem (detect new/modified files)
jaiye-agent sync
```

**Files to change:**
- New file: `src/core/state.ts`
- `src/core/ownership.ts` — use state.json when in standalone mode, git when in git mode
- `src/commands/status.ts` — read from state.json in standalone mode
- New file: `src/commands/touch.ts`
- New file: `src/commands/sync.ts`
- `src/index.ts` — register new commands

### 4. Rich Handoff Format

**Current state:** Handoffs in `src/core/handoffs.ts` capture: id, from, to, timestamp, branch, status, summary, files_touched, notes. Branch is git-specific. Files are just paths.

**Change:** Extend handoff metadata to support non-code context.

```typescript
export interface Handoff {
  id: string;
  from: string;
  to: string;
  timestamp: string;
  branch?: string;           // git mode only
  status: string;
  summary: string;
  files_touched: FileRef[];  // was string[]
  notes: string;
  context?: HandoffContext;
}

export interface FileRef {
  path: string;
  artifact_type?: string;    // 'code' | 'spreadsheet' | 'document' | 'media_ref' | 'project_file'
  description?: string;      // what this file contains / why it matters
}

export interface HandoffContext {
  mode?: string;             // 'implement' | 'review' | 'integrate' | 'draft' | 'decide'
  dependencies?: string[];   // files the receiving agent needs to read first
  decisions_needed?: string[];
  constraints?: string[];
}
```

**Files to change:**
- `src/types.ts` — add `FileRef`, `HandoffContext`, update `Handoff`
- `src/core/handoffs.ts` — serialize/deserialize enriched format
- `src/commands/handoff.ts` — accept `--mode`, `--context` flags

### 5. Bridge Protocol (Built-in)

**Current state:** No bridge concept. The Cowork-Codex bridge was an ad hoc markdown file.

**Change:** Formalize the bridge as a jaiye-agent feature. A bridge is a persistent communication channel between two agents that can't share a terminal session.

```bash
# Create a bridge between cowork and codex
jaiye-agent bridge --between cowork,codex --file bridge.md

# Append a message to a bridge
jaiye-agent bridge --append --agent cowork --message "Source mapping complete" --status done

# Read latest bridge messages
jaiye-agent bridge --read

# Archive old DONE threads
jaiye-agent bridge --archive --older-than 7d
```

The bridge file format follows the protocol established in the Cowork-Codex bridge skill: headers with agent name and timestamp, ACTION/DONE markers, file path references.

Archive behavior:
- Moves threads ending in `DONE:` older than 7 days by default
- Writes archived threads to `<bridge>_archive.md`
- Keeps per-workstream bridges optional through a flag, not the default
- Leaves active ACTION threads in the project bridge

**Files to change:**
- New file: `src/core/bridge.ts`
- New file: `src/commands/bridge.ts`
- `src/index.ts` — register bridge command
- `src/types.ts` — add `BridgeMessage` type

## New Config Format

```yaml
version: 2

project:
  name: "reel-edit"
  type: "media"              # 'code' | 'media' | 'content' | 'research' | 'mixed'

agents:
  - name: cowork
    type: desktop
    description: "Production operations — file transforms, spreadsheets, source mapping"
    capabilities: [file_io, mcp, document_gen]
    bridge: bridge.md

  - name: codex
    type: cli
    description: "Creative direction — edit decisions, pacing, platform strategy"
    capabilities: [code_gen, file_io, reasoning]
    commit_prefix: "[codex]"
    bridge: bridge.md

  - name: claude
    type: cli
    description: "Architecture — complex features, refactoring"
    commit_prefix: "[claude]"

ownership:
  - pattern: "*.xlsx"
    agent: cowork
    artifact_type: spreadsheet
  - pattern: "*.py"
    agent: cowork
    artifact_type: code
  - pattern: "src/**"
    agent: claude
    artifact_type: code
  - pattern: "docs/**"
    agent: codex
    artifact_type: document

settings:
  handoff_dir: ".jaiye/handoffs"
  conflict_mode: "warn"
  base_branch: "main"          # ignored in standalone mode
  bridge_dir: ".jaiye/bridges"
```

## Migration

v0.1 configs (version: 1) work unchanged. The CLI detects config version and applies defaults for new fields. `commit_prefix` remains the primary tracking mechanism in git mode. Standalone features activate only when `.jaiye/` exists outside a git repo or when `project.type` is set to a non-code value.

## Implementation Order

1. **Mode detection** (`src/core/mode.ts`, `src/utils/paths.ts`) — everything else depends on this
2. **State tracking** (`src/core/state.ts`, `src/commands/touch.ts`, `src/commands/sync.ts`) — standalone ownership needs this
3. **Type system** (`src/types.ts` extensions, `AgentDef` updates) — config changes
4. **Rich handoffs** (`src/core/handoffs.ts`, `FileRef`, `HandoffContext`) — builds on types
5. **Bridge protocol** (`src/core/bridge.ts`, `src/commands/bridge.ts`) — builds on state + types
6. **Bridge archive** (`jaiye-agent bridge --archive`) — keeps project bridges from growing forever
7. **Config v2** (migration logic, new fields) — ties everything together
8. **Updated init** (mode-aware scaffolding, agent templates) — user-facing integration
9. **Updated status/check** (standalone paths) — uses state.ts

## Size Estimate

~800-1200 lines of new TypeScript across 6 new files and modifications to 10 existing files. No new dependencies beyond what's already in package.json (js-yaml, picomatch, chalk, cli-table3, commander).
