# Decision Doc — Layer 0

## Problem
jaiye-agent v0.1 only works inside git repos with code artifacts. It cannot coordinate agents working on video edits, content production, hotel ops or research — the work that actually fills the bridge file at `~/Downloads/bridge.md`.

## Why Now
The Cowork ↔ Codex bridge protocol proved the multi-agent coordination pattern works for non-code work, but the bridge is an ad hoc 800+ line markdown file mixing CapCut, jaiye-agent and Akiavic threads. Without tooling, every new project bleeds into the same file. v0.2 is the right time to formalize because the protocol is validated and the failure modes are observable.

## Constraints
- Budget: $0/mo new SaaS spend
- Time limit: ~800-1200 lines of TS across 6 new files plus mods to 10 existing files
- Stack: stay inside existing TS/commander/js-yaml/picomatch/chalk deps. No new packages.
- Backward compat: v0.1 git-mode configs must keep working unchanged

## Build vs Buy
- [x] Checked for existing tools that coordinate multi-agent CLI workflows across non-code projects
- [x] Compared at least 2 alternatives
- Recommendation: **build**
- Reasoning:
  - Aider — multi-agent but git-only, no bridge protocol, no non-code support
  - Continue.dev — IDE-bound, not CLI orchestration across Claude Code + Codex + Cowork
  - Cursor multi-agent — IDE-bound, same limitation
  - LangChain agents — code-level orchestration, not workflow-level handoffs between separate CLI sessions
  - Manual markdown bridges — current state, the messy `bridge.md` proves it doesn't scale past one project
  - The build is narrow: 4 architecture changes already specced in `docs/v0.2-scope.md` + the `bridge --archive` command added by the AI team debate

## Success Criteria
1. `jaiye-agent init` runs cleanly outside a git repo and auto-detects project type with manual override
2. `jaiye-agent touch` and `sync` track ownership in standalone projects via `.jaiye/state.json`
3. `jaiye-agent bridge` creates a project-scoped bridge, accepts append/read and archives DONE threads older than 7 days into `<bridge>_archive.md`
4. v0.1 git-mode workflows pass existing tests with no behavior change
5. The current `~/Downloads/bridge.md` mess can be split into project bridges using the new tooling

## Non-Goals
- Per-agent-pair bridge files as the default (stays an optional flag)
- File hashing in `state.json` for v0.2 (deferred to v0.3 `--strict` mode if mtime conflicts surface)
- Auto-detecting which agent did what without explicit `touch` calls
- Replacing the Cowork-Codex bridge skill — v0.2 produces output compatible with it

## Decision
Ship jaiye-agent v0.2 as specced in `docs/v0.2-scope.md` with one material addition from the multi-AI debate (Claude Code, Codex, ChatGPT, Perplexity): include `jaiye-agent bridge --archive` in the v0.2 bridge command, defaulting to a 7-day cutoff for `DONE:` threads. Without it, "one bridge per project" rots into the same mess in 6 months.

Implementation order from `docs/v0.2-scope.md` stands: mode detection → state tracking → type system → rich handoffs → bridge protocol (now including --archive) → config v2 → updated init → updated status/check.
